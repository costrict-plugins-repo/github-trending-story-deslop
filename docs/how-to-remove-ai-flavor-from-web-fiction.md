# AI 写的小说 AI 味太重怎么办：去AI味的具体做法

去 AI 味要看句子怎样组织、笔墨花在哪里，以及人物的行动是否有依据。Oh Story（`zenstory-ai/oh-story-claudecode`，开源 MIT）的 `/story-deslop`（`/去AI味`）默认完整检查这三层，再按作者授权改稿。可以单独使用，也可以承接长短篇写作流程中的定点修改。

处理前先读当前要求与本书文风。安静场景、短促台词、心理直写和叙述者评论，都要放回具体语境判断。

## 三层分别看什么

| 层 | 常见问题 | 改稿时看什么 |
|---|---|---|
| 表达 | 连续短碎句；长句里逐项播报；套词、套路句与所有人相同的声口 | 围绕行动组织信息，把条件和原因接入动作，恢复人物此刻的说话方式 |
| 叙事用笔 | 无关过程逐步拍出，关键交锋却一句带过；细节只重复命名情绪 | 场景要完成什么，读者需要经历哪个过程，哪些重复可以压缩 |
| 故事因果 | 人物突然改口，条件尚未成立就得到结果，角色知道了不该知道的信息 | 原文或已定设计能否支持选择、变化与结果；缺了什么依据 |

三层各自可以没有问题。词句干净的稿子也可能详略失衡或因果断裂，脚本零命中不能代替完整阅读。方法分别见 [表达](../skills/story-deslop/references/expression.md)、[用笔](../skills/story-deslop/references/narrative-focus.md)与[故事](../skills/story-deslop/references/story-logic.md)。

## 先治理电报体，再看套词

电报体既包括每个动作单独成句，也包括把位置、责任、条件用逗号依次排开的长句。补主语、换标点或把几句接成一句，还可能只是把动作清单拉长。改稿要分出信息主次，让读者跟着人物完成行动；紧张时的短句和人物有意的停顿仍可保留。

长期积累的“深吸一口气”“眼中闪过一丝”“嘴角勾起一抹”“不禁”“仿佛……”以及句式、整段样本保留在[词句信号索引](../skills/story-deslop/references/banned-words.md)。这些是定位线索，命中后还要判断是否重复、空泛或与本书声口不合。不能把每个情绪词都换成垂眼、攥拳等微动作，也不能删掉承担区分和承接的修饰。

## 实际流程

1. **读原文与依据。** 通读本次正文，按需查相关前文、设定与设计，完整检查三层。本地文件先做句式预检，提示只供定位。
2. **找出阅读损失。** 每项问题记录原文位置、具体断点和最小改法，区分可直接修复、资料不足、需要剧情设计。先核对故事成立条件，再安排详略与词句。
3. **按授权改稿。** 普通去味可修表达、恢复已有承接、调整已定内容的详略；需要新增事件、动机、成立条件，或改变结果和揭露顺序时，先给最小设计方案。已获授权的重写直接完成。
4. **回读与复扫。** 对照原文和授权回读完整场景，检查事实、选择、因果、情绪与空间方向，再完成文件扫描。仍像对白提纲或逐项播报时，表达检查尚未完成。

作者只要检测时，只交诊断，不修改正文。指定段落或问题时，只处理该范围；范围外的问题可以提示。也可以按检测类别或问题名（套词句式、情绪、节奏、对话、收尾、解释与安排感）指定检查项，对应关系见[范围接口](../skills/story-deslop/references/deslop-gates.md)，范围不对应轻中重。

## 删除与保留怎样判断

没有叙事功能的内容可以整段删除，不设固定删减率。伏笔、因果、人物选择、情绪体验和揭露顺序要保住；某个过程写得太略，也可能需要展开已有内容。字数仍服从作者给定范围。

逻辑问题会纳入诊断。有原文或已定设计支持的承接可直接恢复；资料不足时说明未知，需要改变剧情时说明备选及影响。不能凭空补证据、冲突或人物经历来让故事显得合理。

## 脚本能做什么

本地预检从 `story-deslop` 技能目录执行，文件参数使用绝对路径：

```bash
node scripts/check-ai-patterns.js --check --fail-on=blocking <正文文件绝对路径>
```

检测器不能判断整篇故事是否成立。表达提示要回到语境复核；写作流程中的 blocking 仍需通过调用方验收。有功能的原句若经作者明确选择，可按既有白名单保留；其余保留表达功能自然改写后复扫，不能只写一条保留说明就宣称通过。

外部 AI 检测报告也只能帮助定位可对应到正文的问题。skill 不承诺检测分数，不靠注水、故意错字或打乱标点改分。
